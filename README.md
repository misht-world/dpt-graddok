# ГРАДДОК

Веб-программа для небольшой проектной группы, которая разрабатывает документацию по планировке территории
(ДПТ, ППТЛ, АГПТ) и согласует её в комитетах. ГРАДДОК отвечает на два вопроса:

- **что пришло** — согласования, отказы, замечания и распоряжения, найденные в папках проектов;
- **что ушло** — выпуски: какой комплект, кому и когда отправлен.

Вместе это даёт срок ответа по каждому комитету («отправлено 16-02 → согласовано 23-03, 35 дней»)
и план-график — без полей, которые нужно заполнять вручную. Поправить вручную при этом можно всё.

Интерфейс — на русском языке.

## Возможности

- **Письма.** Каталог документов из папок проектов: от кого, решение (согласование, отказ, замечания,
  заявление, распоряжение), этап, дата. Фильтры как в Excel, сводная матрица «проект × комитет»,
  просмотр PDF, Word и Excel в браузере, скачивание отдельных файлов и архивом.
- **Выпуски.** Регистрация комплекта по папке (в том числе по срезам резервной копии с меткой адресатов),
  копии файлов на сервере, дерево, сравнение выпусков, потоковый zip без ограничений по размеру.
- **Сроки.** Отправка на каждого адресата, ответ подбирается автоматически (первый документ комитета
  после отправки), повторные круги после замечаний, ручная правка. Матрица и план-график с отметкой
  окончания распоряжения.
- **Проекты, которые ведутся вручную** (АГПТ, концепции): загрузка писем через браузер.
- **Ответы на замечания.** Письмо с замечаниями режется на пункты; к каждому — ответ, примечание (текст
  и картинки вперемешку), статус. Повторные замечания из прошлых писем находятся сами, прошлый ответ
  подставляется черновиком. Сводная таблица по нескольким комитетам и хронология по кругам; всё — в Word.
- **Ссылки для посторонних.** «Поделиться» у письма, выпуска или файла: ссылка на 30 дней, по которой
  видно только этот объект.
- **Пользователи.** Личные входы (e-mail и пароль), роли «просмотр», «исполнитель» (пишет ответы на замечания)
  и «администратор», лимит попыток входа.
- **Телеграм.** Сообщение в чат после обновления каталога: какие письма появились, со ссылкой.
- **Резервная копия.** Ежедневные снимки баз и зеркало файлов в отдельную папку.

Файлы проектов программа только читает: исходные папки монтируются в режиме «только чтение»,
а нужные файлы копируются на сервер (по содержимому, без дублей), чтобы открываться при выключенном ПК.

## Устройство

- Python 3.13, FastAPI, SQLite; статический фронтенд без сборки (HTML, CSS, JavaScript).
- Разбор писем — pdfplumber (только текстовый слой, без распознавания сканов), Word — python-docx.
- Один Docker-контейнер; рассчитано на Raspberry Pi 5, работает и на обычном ПК.
- Без очередей, внешних баз и других сервисов.

```
app/          сервер: сканер папок, разбор имён файлов, каталог, выпуски, отправки, пользователи
static/       интерфейс: «Письма», «Выпуски», «Сроки», панель администратора, просмотр файлов
tests/        pytest
committees.yaml        справочник комитетов (сокращения, полные названия, другие написания)
config.example.yaml    образец настроек
```

## Запуск

На ПК (для пробы):

```bash
pip install -r requirements.txt
cp config.example.yaml config.yaml   # задайте пароли в разделе auth
python run.py
```

Затем откройте адрес из `config.yaml` (по умолчанию http://127.0.0.1:8080), войдите паролем администратора
и в «Панели» добавьте папки с проектами.

В Docker: образ собирается из `Dockerfile`. Настройки и данные лежат вне образа и задаются переменными окружения:

| Переменная | Что это |
|---|---|
| `CONFIG_FILE` | путь к `config.yaml` |
| `COMMITTEES_FILE` | путь к `committees.yaml` (по умолчанию рядом с настройками) |
| `DATA_DIR` | базы и копии файлов |
| `BROWSE_ROOTS` | какие папки показывать в обзоре (через `:`) |
| `PC_PATHS` | как те же папки называются на ПК — для подсказок «куда сохранить» |
| `BACKUP_DIR` | куда класть резервную копию |

Пароли и токены хранятся только в `config.yaml` на сервере и в git не попадают.
